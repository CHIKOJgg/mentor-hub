## Requirements

### R1. Серверная часть на Spring Boot и REST API
Реализовать серверную часть на Java 21 и Spring Boot 3.4.2 GA с базой данных PostgreSQL и миграциями Flyway:
1. REST-контроллеры строго по спецификации docs/ARCHITECTURE_SPECIFICATION.md:
   - `/api/inbox`: очередь отчетов на проверку наставнику (черновики контента ДО публикации: #контент, #рилс, #карусель, #сторителл; распознанные вопросы к наставнику; AI-выжимка рефлексии), согласование и отклонение отчетов.
   - `/api/students`: список и профили учениц, календарь дисциплины с интерактивными тултипами с расшифровкой пропуска, тумблер болезни/паузы «В строю 🔥 / Болеет ☕» с заморозкой стрика (воскресенье — официальный выходной).
   - `/api/analytics`: расчет 10 сквозных метрик (Reels, Карусели, Сторителлы, Рассылки, Выручка, Средний чек, Рост дохода Точка А -> Точка Б, Рост чека, Новые клиенты, AI-рефлексия), генерация текста кейсов для сторис.
   - `/api/tasks`: управление заданиями и правилами хэштегов.
   - `/api/system`: мониторинг состояния системы и Zoom-трекер (фиксация даты следующего созвона и счётчик проведенных встреч).
2. Двухуровневый доступ администраторов: Ксения (Главный ментор) и Катя (Куратор) с беспарольным входом по magic-ссылкам (таблица admin_tokens).

### R2. Telegram-бот и сервисы обработки отчетов
Интегрировать Telegram-бота (TelegramBots 10.3), работающего в индивидуальных мини-группах «Ксения + Катя + Ученица + Бот» от своего имени (как заботливый ассистент, без участия в общем чате потока):
1. Режим подключения: Long Polling по умолчанию (для локального запуска и docker-compose) с поддержкой переключения на Webhook через конфигурацию.
2. Прием и обработка черновиков контента ДО публикации по хэштегам (#контент, #рилс, #карусель, #сторителл), защита от дублей (SHA-256) и антифрод.
3. AI-выжимка рефлексии (Spring AI): суммаризация голосовых сообщений и видеосообщений (кружочков) в 3 структурированных буллета (эмоции/затык, действия за день, вопрос к Ксении). Подключение к внешнему API LLM через переменные окружения, с автоматическим мок/стаб-фолбэком при отсутствии API-ключа для локальной разработки и офлайн-тестов.
4. Фоновый планировщик (@Scheduled): ежедневные вечерние напоминания о сдаче отчетов, субботний автоопрос в 18:00 по новым клиентам и выручке.

### R3. Контейнеризация и инфраструктура
